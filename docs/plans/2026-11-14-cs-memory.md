# CS Memory (Vector Knowledge) Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** One shared, searchable knowledge memory (pgvector in this project's Supabase) that every channel — voice calls, email, web contact form — can use, switched off by default so today's behaviour is unchanged.

**Architecture:** Knowledge markdown (copied from the Shopify chatbot) is chunked, embedded with OpenAI and stored in a Supabase `kb_chunks` table. `apps/ai-agents` owns search (`app/memory/`). Email, web and post-call drafts get relevant snippets in the response agent; live voice calls get a new Vapi tool `search_knowledge` that goes Vapi → API → ai-agents. Everything is gated by `KNOWLEDGE_SOURCE=static|vector` (default `static`).

**Tech Stack:** Python 3.12 / FastAPI / supabase-py / OpenAI embeddings (`text-embedding-3-small`, 1536 dims) · Fastify + zod · Supabase Postgres + pgvector.

## Decisions

| Decision | Chosen | Alternatives | Why |
|---|---|---|---|
| Vector DB | pgvector in this project's Supabase | Shared AWS RDS; Chroma in image; Google Vertex | Already reachable from Vercel; no new infra; vectors survive deploys |
| DB access | supabase-py (`table().upsert`, `rpc()`) | psycopg + connection string | Zero new dependencies; HTTPS works on Vercel serverless; no pooling issues |
| Embeddings | OpenAI `text-embedding-3-small` | bge-base (chatbot) | Runs on Vercel (no torch); OpenAI key already configured |
| Where search lives | `apps/ai-agents/app/memory/` | New package / new service | Smallest change; reuses existing clients |
| Table location | `public.kb_chunks`, RLS on, no policies | Custom `cs_memory` schema | Custom schemas must be exposed in PostgREST; RLS-with-no-policies = service role only |
| Reversibility | `KNOWLEDGE_SOURCE` default `static`; down migration; feature branch | — | User requirement: must be able to go back |
| `joola_internal_policies.md` | **Excluded** pending confirmation | Include | Looks like test fixture ("custom knowledge file"); risk of promising a non-existent offer |
| Generic (non-warranty) emails | Out of scope | Add AI answers | They currently get a canned acknowledgement with no AI; adding AI there is a new feature |

## Tasks

1. **Knowledge files** — copy 3 chatbot files to `knowledge/shopify/`. Verify: files identical (`diff`).
2. **Migration** — `migrations/memory/0001_kb_chunks.up.sql` / `.down.sql` (extension, table, HNSW index, RLS, `match_kb_chunks` RPC). Not auto-applied.
3. **Config** — `knowledge_source` (`static`|`vector`, default `static`), `embedding_model`. Test: default is `static`; invalid value rejected.
4. **Chunker** (`app/memory/chunker.py`) — split on `##` headings, 500 chars / 75 overlap, stable sha256 hash. Tests first.
5. **Store + search** (`app/memory/store.py`, `app/memory/service.py`) — `search_knowledge()` returns `[]` when static, on error, or on empty query; never raises. Tests first (fake store / fake OpenAI).
6. **Ingest** (`app/memory/ingest.py`, `python -m app.memory.ingest`) — only embeds new chunks, deletes chunks no longer in source. Tests first.
7. **Response agent** — when `vector`, add `relevant_knowledge` to the user message. Test: `static` → prompt byte-identical to today.
8. **ai-agents endpoint** `POST /tools/search_knowledge` → `{enabled, results}`. Tests first.
9. **API (voice path)** — `searchKnowledge` on the ai-agents client, `/api/tools/search_knowledge` route (degrades to `enabled:false` if ai-agents is down), register route, add to Vapi `TOOL_PATHS`. Verify: `tsc --noEmit` (API has no test runner).
10. **Vapi config** — `tools/search_knowledge.json` + one row in `system-prompt.md` §3. **Not pushed to Vapi** until approved.
11. **Verify** — full ai-agents suite + API typecheck; code review.

## Go-live (manual, needs approval — not done by this plan)

1. Supabase SQL editor: run `migrations/memory/0001_kb_chunks.up.sql` on the **dev/demo** project.
2. `cd apps/ai-agents && uv run python -m app.memory.ingest` (uses `.env.local`).
3. Set `KNOWLEDGE_SOURCE=vector` in Vercel (ai-agents) and redeploy.
4. `apps/vapi-setup` recreate to push the new `search_knowledge` tool to Vapi.

## Rollback

- Set `KNOWLEDGE_SOURCE=static` (or remove it) → identical to today, no deploy of code needed.
- Run `migrations/memory/0001_kb_chunks.down.sql` → table + function removed.
- Branch `feat/cs-memory` not merged, or `git revert` the merge.
